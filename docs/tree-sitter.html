decisão de projeto

Por que o agentq lê o código como uma árvore

O agentq precisa achar criptografia que computadores quânticos conseguem quebrar. Para isso ele não procura palavras: ele entende a estrutura do código, usando uma biblioteca chamada tree-sitter.

Em uma frase: o tree-sitter transforma o código em uma árvore, e a árvore permite separar o que é uso real de criptografia do que é só uma menção (comentário ou texto).
1 · o problema

Uma busca por texto se confunde fácil

Veja um arquivo com três linhas que falam de md5, um algoritmo fraco. Só a última linha realmente usa. Aperte repetir se perder a animação.

Na busca por texto, comentários e frases entram na conta e geram falsos alarmes. Quem lê o relatório perde tempo, e perde a confiança na ferramenta.

2 · como funciona

O código vira uma árvore de peças

O tree-sitter lê a linha e a divide em partes com nome, ligadas entre si, como uma árvore genealógica. Cada peça sabe o que é: uma chamada, um módulo, um texto.

3crypto.createHash('md5');

Um comentário ou um texto solto nem aparece como chamada nessa árvore. Por isso o agentq só olha as peças que são chamadas de verdade.

5 · a decisão

Decisão: tree-sitter, porque o projeto precisa distinguir uso real de menção e inferir o propósito de cada chave. A mesma biblioteca já tem gramáticas de JavaScript, TypeScript, Python, Java e Go, então a ideia serve para as próximas linguagens.

  • O que o tree-sitter não resolve: ele vê a forma do código, não o seu significado em execução.
  • Se o algoritmo vem de um parâmetro de função, como digest(algoritmo), ou de uma configuração externa, a árvore não sabe o valor, e o agentq não reporta esse caso. Está registrado como limitação conhecida no README.
